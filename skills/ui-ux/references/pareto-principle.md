# Princípio de Pareto

## Princípio

Uma pequena parte das causas costuma produzir a maior parte dos efeitos; aproximadamente 80% dos resultados vêm de 20% das causas.

## Aplicação

- Priorize as tarefas e fluxos mais usados.
- Destaque as ações de maior impacto.
- Otimize primeiro os caminhos críticos.
- Não trate todas as funcionalidades com o mesmo peso visual.
- Use dados de uso para priorizar melhorias.

## Exemplo

Se a maioria dos usuários usa busca, listagem e detalhe, essas telas devem receber prioridade de design e performance.

## Sinal de violação

- Funcionalidade rara recebe o mesmo destaque que fluxo essencial.
- Esforço de design concentrado em caso de uso secundário.
- Fluxo principal é mais difícil que fluxo avançado.
